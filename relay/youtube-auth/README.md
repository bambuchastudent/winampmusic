# Isolated YouTube TV metadata authorization experiment

This Worker exists only for the manual page in `experiments/youtube-auth/`. It is **not** the anonymous playback relay and is not deployed by the Pages workflow. It has no storage. All credential requests require an exact HTTPS `APP_ORIGIN`; without it the Worker rejects every request. An Origin check is a browser boundary, not server-side authentication. Restrict access to the test deployment independently if needed.

Create your own Google Cloud OAuth client of type **TV and Limited Input devices** for a project on which the YouTube Data API is enabled, configure its consent screen and test users as applicable, and use only its assigned ID and optional secret. Do not use YouTube TV's application identity. The requested scope is `https://www.googleapis.com/auth/youtube.readonly`. Google documents device authorization for limited-input devices; a browser-capable production app should choose an appropriate supported flow separately. This research page makes no production OAuth recommendation.

Deploy this Worker separately with the exact origin of the HTTPS page set as `APP_ORIGIN` (for example, `https://operator.example`, without a trailing slash or path). Serve the standalone `index.html` and `experiment.mjs` from that origin, then enter the Worker's HTTPS origin and your own client ID/secret into the page. Do not host the page with a static HTML service that logs form fields or injects third-party scripts. Do not add this relay to the app's ordinary playback config or deploy workflow. No real account authorization is performed by the repository tests.

The only routes are `POST /oauth/device`, `/oauth/token`, `/oauth/revoke` and `POST /tv/player`, `/tv/next`, plus same-origin preflight. The first three forward form fields to fixed Google OAuth endpoints; TV requests forward JSON to fixed YouTube InnerTube endpoints. Redirects, unknown routes, methods, origins, cookies, extra OAuth fields, and arbitrary target URLs are rejected. The Worker does not proxy video media, save tokens, or reflect supplied values in errors. Keep HTTP request-body logging disabled at the hosting edge.

Follow the direct `google.com/device` link in the page and enter the displayed code. Compare one 11-character video ID. The exported JSON deliberately includes only fixed OAuth/status enums, video ID, playability enum, audio format count, whether the experimental transport sent a bearer header, and `playback: "untested"`. An OAuth grant only means Google issued a token. A TV `OK` or `LOGIN_REQUIRED` response does not prove whether the private TV interface accepted the bearer token; the report keeps provider acceptance `unknown`. Formats are only metadata; this experiment does not request audio bytes or verify actual playback. Reload or cancel to clear in-memory authorization; use Sign out to attempt revocation, which needs network access.

Run `node tests/youtube-auth-experiment-v190.mjs` from the repository root. This mock-only suite verifies the fixed transport, stale response handling, polling, instance isolation, and report redaction. The real Google device flow, operator consent configuration, private TV acceptance, and actual playback remain unverified until an operator runs a controlled manual trial.
