# Apple-origin full playback requirements

## Requirement: Apple catalog IDs are not playback handles

An Apple song or album import MUST preserve Apple catalog identifiers as provider evidence and MUST NOT encode them into a generic 11-character playable ID.

### Scenario: catalog metadata without a resolver result

- GIVEN an Apple track has a numeric catalog ID, title, and artist
- AND no strict full playback source can be resolved
- WHEN it is imported
- THEN the recording remains in the library
- AND its Apple catalog ID is preserved
- AND it is not counted as playable/matched
- AND no synthetic YouTube-shaped ID is created

## Requirement: full resolver results are counted honestly

A track MUST be counted as playable/matched only when a real full playback handle was resolved for the current client.

### Scenario: partially resolved album

- GIVEN an Apple album contains two readable tracks
- AND exactly one track resolves to a real YouTube video ID
- WHEN the album is imported
- THEN both recordings are kept in album order
- AND the completion state reports one playable track and one unresolved track
- AND Add & Play starts the resolved recording

## Requirement: previews are not normal playback

A short Apple catalog preview MUST NOT be treated as successful full playback.

### Scenario: only preview metadata exists

- GIVEN an Apple recording exposes a short preview
- AND MusicKit is unavailable
- AND no full resolver result exists
- WHEN playback is requested
- THEN AMPULAMP keeps the recording unresolved
- AND MUST NOT report the preview as the complete playable recording

## Requirement: resolved YouTube fallback remains playable

A real resolved YouTube handle MUST remain playable through the existing iframe player if the optional direct-audio path fails.

### Scenario: proxy/direct audio failure

- GIVEN an Apple-origin recording has a real resolved YouTube video ID
- AND direct/proxy audio fails
- WHEN playback is requested
- THEN AMPULAMP invokes the original YouTube iframe playback path for that same recording
- AND MUST NOT finish with `NO PLAYABLE SOURCE` solely because the proxy failed

## Requirement: old synthetic Apple IDs are migrated

The client MUST recognize only the exact deterministic synthetic Apple IDs generated by the prior catalog-first implementation and migrate them to provider-independent local recording IDs.

### Scenario: existing broken library

- GIVEN a saved Apple track has the old deterministic synthetic ID corresponding to its `appleTrackId`
- WHEN the new runtime starts
- THEN the synthetic ID is removed as a playback handle
- AND the recording is retained with title, artist, and Apple evidence
- AND the track can be resolved again normally

## Requirement: MusicKit remains preferred when configured

The resolver MUST NOT replace successful Apple-native MusicKit playback.

### Scenario: authorized MusicKit playback

- GIVEN valid MusicKit deployment credentials and an authorized subscriber
- WHEN an Apple-origin track is played
- THEN MusicKit may play the exact Apple catalog song first
- AND YouTube remains a fallback rather than canonical identity
