# Design

The standalone page `experiments/youtube-auth/index.html` imports `experiment.mjs` only when opened. It needs a separately deployed `relay/youtube-auth/worker.js`; neither the application loader nor normal anonymous relay references it. The browser keeps one client identity, device code, access/refresh token pair, poll deadline, and optional TV session per page instance, only in closure memory. No service worker, storage, logging, or automatic resume.

The relay has fixed `POST /oauth/device`, `/oauth/token`, `/oauth/revoke` mappings to Google, and `POST /tv/player`, `/tv/next` to `www.youtube.com/youtubei/v1/`. It accepts JSON for OAuth, translates to Google's form encoding, and returns bounded parsed fields. TV transport permits a Bearer header only on `/tv/*`, rejects cookies, drops upstream response headers, follows no redirects, and never proxies arbitrary URLs or media. It rejects requests outside an operator-set exact `APP_ORIGIN` and manually opted-in worker deployment. An Origin check constrains browser access but is not server-side authentication; operators must limit exposure of this test relay.

The browser obtains Google's device code using its own configured OAuth client and `youtube.readonly` scope, opens Google's verification site directly, polls no faster than the provider interval, and refreshes with the same client. Cancel invalidates the generation and clears the code; logout clears all memory first then attempts Google token revocation. Late replies cannot restore a canceled or signed-out session. A second page/controller instance has separate closure state. Provider failures expose only fixed stage/status codes.

For the comparison, separate YouTube.js 18.0.0 TV instances use a transport that permits only the two TV InnerTube paths through the experimental relay. The authorized instance receives provided token credentials through `session.signIn(credentials)` so the library does not discover/borrow the YouTube TV application's identity. The pinned HTTPClient injects the Bearer header for a signed-in InnerTube session in browsers; `getBasicInfo(id, { client: 'TV' })` selects TV explicitly. A probe records fixed playability status, audio format count, and whether the experimental fetch forwarded a bearer header, without requesting media. Neither `OK` nor `LOGIN_REQUIRED` alone confirms the bearer was accepted or rejected; provider acceptance stays `unknown`. Stream and actual playback remain `untested`. An OAuth success never becomes a playback success claim. Probe cancellation aborts pending transport and prevents late setup from issuing a new request.

This is a manual research prototype. Google's device flow documentation targets actual limited-input devices and recommends other OAuth flows on browser-capable platforms. TV InnerTube is a private interface; provider acceptance must be observed, not assumed. Only the manual operator experiment uses this code.
